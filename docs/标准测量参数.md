# 标准测量参数

| 项 | 内容 |
| --- | --- |
| 文档版本 | 2026-10-10 |
| 读者 | IPS 开发人员 |
| 用途 | 约定每种设备能测哪些参数、参数名称和类型。不包含零件、部位等业务对象 |
| 维护方 | 测量工位适配程序一方。IPS 不注册、不修改本文 |

本文是发给 IPS 的参数标准。原先称为测量主数据。IPS 按本文的 `deviceType` 和参数 `code` 发起测量，并按同样的编码识别回调结果。不提供注册、查询或更新这些参数的接口。

参数有增减时，由我方发布本文的新版本，并同步到工位机。IPS 以收到的最新版本文档为准。

配套接口见《面向 IPS 的设备测量接口》。

---

## 1. 结构

整份标准有一个版本号。一种设备下面有一组参数。每个参数有编码、名称、类型和说明。

| 字段 | 说明 |
| --- | --- |
| version | 本版标准的版本号。回调和健康检查里的 `standardRevision` 等于它。本期为 `2026-10-10` |
| deviceType | 设备类型编码。发起测量时写入 `deviceType` |
| 名称 | 设备中文名，与编码一一对应 |
| code | 参数编码。发起请求和回调结果都使用它 |
| 名称 | 参数中文名。回调结果中的 `name` 与此一致 |
| valueType | `number`、`string`、`boolean`、`image` |
| unit | 单位。没有单位的参数不填。回调里没有单位时为 `null` |
| 说明 | 这个参数在设备上测的是什么。不表示零件或部位。供 IPS 对照，不出现在发起报文里 |

`valueType` 决定回调里 `value` 的形态：

| valueType | value |
| --- | --- |
| number | JSON 数字 |
| string | JSON 字符串 |
| boolean | JSON 布尔 |
| image | 图片对象数组。一张图也放在数组里。对象含 `mimeType`、`fileName`、`contentBase64` |

一次测量可以只请求该设备参数中的一部分。请求里的 `code` 必须属于该设备在本文中的参数。同一请求里 `code` 不重复。

---

## 2. 业务含义由 IPS 维护

本文只规定设备能测什么。`inner_diameter` 表示内径这一项测量，不表示它属于哪一个零件、哪一个部位。

业务上的测量对象由 IPS 维护。本程序不建立、不保存「这次内径是作动筒内径」这类关系，也不因业务变化去改标准参数。

常见有两种情况：

1. **业务对象是明确的。** 例如这次要测的是作动筒内径。IPS 仍请求手持式三坐标的 `inner_diameter`。作动筒、工卡、部位写在请求的 `context` 里。回调会把 `context` 原样带回，IPS 用它把结果记回自己的业务。
2. **业务对象是含糊的，或者当时没有明确目标。** 例如数字千分尺只量一个外径，还不对应到具体零件。IPS 只请求 `outer_diameter`，`context` 可以不写。

`context` 的字段由 IPS 自己定。适配程序不解释、不校验，也不把它当成标准参数。

作动筒内径的发起示例：

```json
{
  "taskId": "018f1a2b-3c4d-7e5f-8a9b-0c1d2e3f4a5b",
  "deviceType": "handheld_cmm",
  "params": [
    { "code": "inner_diameter", "requirement": { "nominal": 50.0, "upper": 0.02, "lower": -0.02 } }
  ],
  "context": {
    "bizObject": "作动筒内径"
  }
}
```

数字千分尺没有明确测量目标时，可以不带业务对象：

```json
{
  "taskId": "018f1a2b-3c4d-7e5f-8a9b-0c1d2e3f4a5c",
  "deviceType": "digital_micrometer",
  "params": [
    { "code": "outer_diameter" }
  ]
}
```

两种请求用的都是第 5 节里的参数编码。差别只在 IPS 自己的 `context`。

## 3. 和工位机内部映射的关系

现场设备的品牌、型号不同，设备自己的字段名、通信口和协议也不同。工位机内部另有一份映射，把这台机器上设备的原始参数对应到本文的标准参数。

这份映射由我方在工位机上维护。IPS 不维护映射，接口里也不出现设备原始字段、品牌和型号。更换同类型设备的品牌或型号时，我方改工位机上的映射，本文的 `deviceType` 和参数 `code` 不变。

测量项目本身变化时（例如某种设备从现有参数再增加一项，或内窥镜在现有截图之外再增加录像），我方修改本文，把 `version` 改为新版本号后发给 IPS，同时更新工位机上的标准参数和内部映射。已经接受、尚未回调的任务，仍按接受时的那一版参数回传。

## 4. 设备类型

| 名称 | deviceType |
| --- | --- |
| 内窥镜 | `endoscope` |
| 手持式三坐标测量仪 | `handheld_cmm` |
| 数字测量千分尺 | `digital_micrometer` |
| 拍照相机 | `camera` |
| 挠度工装测量仪 | `deflection_gauge` |

编码固定。发起测量时写编码，不写中文名称。

## 5. 现行参数

本版 `version` 为 **`2026-10-10`**。工位机回调和健康检查中的 `standardRevision` 使用这个值。IPS 用它确认结果依据的是哪一版参数。

一次测量可以只请求下表中的一部分 `code`。不能请求表中没有的编码。

### 5.1 内窥镜 `endoscope`

| code | 名称 | valueType | unit | 说明 |
| --- | --- | --- | --- | --- |
| observation | 观测结论 | string | — | 对可见表面的总体结论，如腐蚀、裂纹、剥落、无异常 |
| defect_location | 缺陷位置 | string | — | 缺陷所在位置，如轴向距离、周向或时钟方位 |
| snapshot | 内窥图像 | image | — | 确认后的截图。一张或多张都放在 `value` 数组里 |

### 5.2 手持式三坐标测量仪 `handheld_cmm`

| code | 名称 | valueType | unit | 说明 |
| --- | --- | --- | --- | --- |
| inner_diameter | 内径 | number | mm | 被测孔或筒体内径 |
| roundness | 圆度 | number | mm | 同一截面轮廓相对理想圆的偏差 |
| cylindricity | 圆柱度 | number | mm | 沿轴向各截面合成的圆柱偏差 |
| guide_wear | 导向段磨损量 | number | mm | 导向段相对原始尺寸的磨损量 |
| coaxiality | 同轴度 | number | mm | 被测轴线相对基准轴线的同轴偏差 |

### 5.3 数字测量千分尺 `digital_micrometer`

| code | 名称 | valueType | unit | 说明 |
| --- | --- | --- | --- | --- |
| outer_diameter | 外径 | number | mm | 外圆直径 |
| length | 长度 | number | mm | 轴向长度 |
| thickness | 厚度 | number | mm | 壁厚、片厚或层厚 |

### 5.4 拍照相机 `camera`

| code | 名称 | valueType | unit | 说明 |
| --- | --- | --- | --- | --- |
| overview | 全貌照片 | image | — | 零件整体外观。可多张 |
| detail | 局部照片 | image | — | 缺陷或测量部位特写。可多张 |
| remark | 拍摄说明 | string | — | 拍摄部位、光线或现场备注 |

### 5.5 挠度工装测量仪 `deflection_gauge`

| code | 名称 | valueType | unit | 说明 |
| --- | --- | --- | --- | --- |
| span | 测量跨距 | number | mm | 两支点之间的距离 |
| deflection | 挠度 | number | mm | 加载后测得的挠度 |
| residual_deflection | 残余挠度 | number | mm | 卸载后残留的变形 |

## 6. 发起与回调时怎么用

发起测量时，`deviceType` 取第 4 节的编码，`params[].code` 取第 5 节该设备下的 `code`。可以少请求几项，不能请求表中没有的编码。

回调成功时，`results` 与本次请求的参数一一对应，顺序相同。每一项的 `code`、`name`、`valueType`、`unit` 以本文为准。

手持式三坐标一次测内径、圆度、圆柱度和导向段磨损量：

```json
{
  "taskId": "018f1a2b-3c4d-7e5f-8a9b-0c1d2e3f4a5b",
  "deviceType": "handheld_cmm",
  "params": [
    { "code": "inner_diameter", "requirement": { "nominal": 50.0, "upper": 0.02, "lower": -0.02 } },
    { "code": "roundness", "requirement": { "upper": 0.015 } },
    { "code": "cylindricity", "requirement": { "upper": 0.02 } },
    { "code": "guide_wear", "requirement": { "upper": 0.20 } }
  ]
}
```

`requirement` 不是标准参数的一部分。它是这一次测量的要求，例如公称值和偏差。适配程序不解释其字段，回调时原样带回。字段含义由 IPS 自定。

对应回调中的一项：

```json
{
  "code": "inner_diameter",
  "name": "内径",
  "valueType": "number",
  "unit": "mm",
  "value": 49.998,
  "requirement": { "nominal": 50.0, "upper": 0.02, "lower": -0.02 }
}
```

内窥镜截图、拍照相机的全貌或局部照片，`value` 都是图片数组。一张图也放在数组里：

```json
{
  "code": "snapshot",
  "name": "内窥图像",
  "valueType": "image",
  "unit": null,
  "value": [
    {
      "mimeType": "image/jpeg",
      "fileName": "bore-1.jpg",
      "contentBase64": "/9j/4AAQSkZJRg..."
    }
  ]
}
```

回调中的 `standardRevision` 等于本版 `version`，本期为 `2026-10-10`。
