# 异常呼叫

工位提交呼叫后，IPS 记下类型和流水。接收端 `app-notification-reciver` **留到下一阶段**，本轮不建工程、不写程序。

## 呼叫类型

实体 `IPS/service/CallType`，表 `public."IPS_service_CallType"`。

| 字段 | 含义 |
|------|------|
| typeCode | 编码。预置 `tool_fault`、`equipment_fault`（名称都是设备故障）、`tech_help`、`personnel`、`material` |
| typeName | 名称 |
| enabled | 是否启用。工位弹窗只列出已启用的 |
| soundEnabled | 是否发声，默认关闭 |
| soundKey | 声音标识：`beep` 提示音、`alarm` 警报、`chime` 铃声 |
| roleIds | 角色 id 的 JSON 数组。选项来自 EADAF `GET /api/v1/roles`，由 IPS BFF `GET /api/ips/call-roles` 转发当前用户令牌 |

IPS「高级产线业务」里可以增删改。页面：`/line/call-types`。

## 呼叫流水

沿用 `IPS/service/NotificationLog`，补了这些列：

| 字段 | 含义 |
|------|------|
| status | `sent` 已发出、`accepted` 已接受、`completed` 处理完成、`cancelled` 已取消 |
| callerName | 呼叫人 |
| acceptedBy | 接受人 |
| acceptedAt | 接受时间 |
| completedAt | 完成时间 |

`isResponded` 在已接受和完成后为 true。工位提交时写入 `sent`。流水页 `/line/call-logs` 只读，可按状态筛选。

## 工位

呼叫弹窗读取已启用的类型，不再使用写死列表。

顶栏右侧、AGV 之前有一颗喇叭，只代表本工位最近一条呼叫：

- 已发出：橙色
- 已接受：蓝色
- 处理完成：绿色
- 已取消、发出超过 10 分钟、或本工位又提交了更新的呼叫：这颗按钮去掉。新呼叫自己再出现一颗橙色按钮

点击后看到问题描述、类型、当前状态、接受人、接受时间和完成时间。工位每 4 秒重新读取这条呼叫，接收端改状态后颜色会变。

## 下一阶段：app-notification-reciver

目录已留在仓库根下，这一阶段不要往里面写程序。

做法对齐 `measurement-exe`：Windows 7 及以上的托盘程序，面板在屏幕右下角。配置放在程序旁边的 `config.json`，至少包含服务地址和登录身份。

它按登录用户的角色接收呼叫：类型上的 `roleIds` 与该用户角色有交集才弹出。`soundEnabled` 为真时播放 `soundKey` 对应的声音。操作员可以把这条流水改成已接受、处理完成或已取消，并写下接受人或完成时间。已接受和处理完成时把 `isResponded` 设为 true。
