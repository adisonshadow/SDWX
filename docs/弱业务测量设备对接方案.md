# 多类型测量设备通用对接API接口设计方案（修订完整版）
## 一、方案背景与核心问题梳理
### 1.1 业务场景
用户通过网页端上游业务系统发起测量请求，调用部署在本地PC上的适配服务；PC通过串口、USB等物理接口对接各类工业测量设备，完成测量并回传标准化数据。
当前接入设备：手持式探针三坐标测量仪、挠度测量工装、数字化千分尺；后续扩展：带测量功能内窥镜及其他新增测量设备。
业务特征区分：
1. 数字化千分尺：单次测量，返回单值，无需人工多次采样确认；
2. 手持式三坐标、挠度工装、内窥镜：支持多次人工采样，操作员采集多组数据后，选择其中一组作为最终结果提交。

### 1.2 方案设计目标
1. 通用性兼容：一套API模型适配全部现有及未来新增测量设备；
2. 高可扩展Mapping：逻辑设备、业务参数与底层硬件解耦，更换硬件无需修改上游业务代码；
3. 异步任务模型：统一支持自动单次测量（千分尺）、人工多次采样确认（三坐标/内窥镜）两类业务；
4. 完整状态机与异常处理：覆盖设备未就绪、断线、通信异常、任务超时、主动取消场景；
5. 资源安全：硬件端口互斥占用，任务结束/异常自动释放串口/USB资源。

## 二、整体架构设计
三层架构：上游业务系统（网页服务端） ↔ PC本地适配服务（核心中间层，承载Mapping、任务管理、设备通信） ↔ 物理测量设备（串口/USB）
1. 上游业务系统：发起测量任务、轮询/接收Webhook状态通知、读取标准化测量结果、业务存储；上游**只使用逻辑设备ID、业务语义参数，不感知COM口、硬件协议、硬件原始字段**；
2. PC本地适配服务：
    - 两层Mapping配置解析（设备实例映射 + 参数映射）；
    - 异步任务生命周期管理、状态机流转；
    - 底层串口/USB通信、设备握手、原始数据采集；
    - 原始硬件数据 → 业务标准化数据转换、单位换算；
    - 端口资源锁、超时控制、日志持久化；
3. 物理测量设备：三坐标、挠度工装、千分尺、内窥镜等。

> 核心设计思想：**逻辑层与硬件层隔离，异步任务模型统一所有设备，Mapping完成双向参数转换，向上游输出固定结构业务数据**。

## 三、两层Mapping映射机制（核心，实现硬件变更上游无感）
映射配置持久化存储在PC本地适配服务，采用JSON/YAML配置，支持热加载，修改配置无需重启服务。分为**设备实例映射**、**测量参数映射**。

### 3.1 设备实例映射（Device Mapping）
作用：上游传入`logicDeviceId`（业务层固定逻辑设备ID）映射到PC本地真实物理硬件信息。
映射配置示例：
```json
{
  "logicDeviceId": "HAND_PROBE_3D_01",
  "deviceType": "COORDINATE_3D",
  "physicalPort": "COM5",
  "vendorModel": "XX品牌手持式三坐标 V2",
  "protocolProfile": "coord_vendor_a_profile",
  "active": true
}
```
字段说明：
- logicDeviceId：上游业务系统唯一识别ID，固定不变；
- deviceType：设备大类编码（MICROMETER/COORDINATE_3D/DEFLECTION/ENDOSCOPE）；
- physicalPort：物理接口，COM3 / USB-01；
- vendorModel：硬件型号，仅用于日志；
- protocolProfile：通信协议配置索引（波特率、校验位、指令模板、解析规则）；
- active：是否启用该设备。

变更场景：更换同类型不同品牌三坐标，仅修改physicalPort、protocolProfile，上游所有接口、业务代码无需改动。

### 3.2 测量参数映射（Param Mapping）
双向映射：上游**业务参数** ↔ 底层硬件指令参数；硬件原始返回字段 → 标准化业务输出字段，包含单位换算。
映射配置示例：
```json
{
  "logicDeviceId": "HAND_PROBE_3D_01",
  "paramMap": {
    "input": {
      "businessField": "targetPointCount",
      "hardwareField": "sample_cnt"
    },
    "outputFieldMap": {
      "hardware.x": "business.coordX",
      "hardware.y": "business.coordY",
      "hardware.z": "business.coordZ"
    },
    "unitConvert": {
      "hardwareUnit": "μm",
      "businessUnit": "mm",
      "scale": 0.001
    }
  }
}
```
- input：上游业务参数名称，自动翻译成底层硬件指令参数；
- outputFieldMap：硬件返回原始字段映射为业务标准字段；
- unitConvert：统一单位换算，无论底层设备输出μm、inch，向上游统一输出业务指定单位。

内窥镜扩展：映射配置可增加多媒体字段映射，硬件原始图片路径/二进制数据映射为业务层image附件字段，测量尺寸数据同样走字段映射。

## 四、核心API接口设计（异步任务模型）
全部接口采用REST，JSON交互；上游业务系统调用【创建任务、查询任务、取消任务】；PC本地操作员界面调用【提交选中样本】。

### 4.1 接口清单
1. POST /api/device/task/create 创建测量任务（上游调用）
2. GET /api/device/task/query 查询任务状态与数据（上游调用，支持轮询）
3. POST /api/device/task/cancel 取消任务（上游/本地操作员调用）
4. POST /api/device/task/submit 提交选定测量样本（PC本地操作员界面调用）

可选扩展：Webhook回调配置，任务状态变更时PC适配服务主动推送状态至上游业务系统，减少轮询。

### 4.2 接口1：创建测量任务 POST /api/device/task/create
请求入参
```json
{
  "requestId": "REQ-20261010-001",
  "logicDeviceId": "HAND_PROBE_3D_01",
  "businessParams": {
    "targetPointCount": 10,
    "tolerance": 0.01
  },
  "taskTimeout": 300000
}
```
参数说明
|参数|类型|必填|说明|
| ---- | ---- | ---- | ---- |
|requestId|string|是|上游请求唯一ID，链路追踪|
|logicDeviceId|string|是|业务逻辑设备ID，用于Mapping查找硬件信息|
|businessParams|object|否|业务侧测量参数，Mapping自动转换为硬件指令参数，无参数传{}|
|taskTimeout|int|否|全局任务超时时间，单位毫秒，默认300000（5分钟）|

成功响应
```json
{
  "code":200,
  "msg":"任务已创建",
  "requestId":"REQ-20261010-001",
  "taskId":"TASK-20261010-0001",
  "taskStatus":"CREATED"
}
```
> 任务创建成功，仅在PC本地生成任务记录，**不阻塞等待测量完成**。

### 4.3 接口2：任务状态查询 GET /api/device/task/query?taskId=TASK-20261010-0001
响应示例
```json
{
  "code":200,
  "msg":"查询成功",
  "requestId":"REQ-20261010-001",
  "taskId":"TASK-20261010-0001",
  "logicDeviceId":"HAND_PROBE_3D_01",
  "taskStatus":"PENDING_CONFIRM",
  "taskMsg":"已采集多组样本，等待操作员选择提交",
  "sampleList":[
    {
      "sampleIndex":0,
      "rawData":{},
      "businessData":{},
      "sampleTime":"2026-10-10 14:20:01"
    },
    {
      "sampleIndex":1,
      "rawData":{},
      "businessData":{},
      "sampleTime":"2026-10-10 14:20:15"
    }
  ],
  "finalResult":null,
  "errorCode":null,
  "errorMsg":null
}
```
任务状态枚举（状态机）
|状态码|说明|
| ---- | ---- |
|CREATED|任务创建完成，等待设备握手就绪|
|DEVICE_READY|串口/USB通信建立成功，等待操作员启动测量|
|MEASURING|正在采集测量，可多次追加采样样本|
|PENDING_CONFIRM|已采集多组样本，等待操作员选定样本提交（人工多测场景）|
|COMPLETED|任务完成，finalResult包含经过Mapping转换后的标准化业务数据|
|FAILED|任务失败（设备未就绪、通信中断、硬件报错）|
|TIMEOUT|全局任务超时，任务终止|
|CANCELLED|任务被主动取消|

- 状态为`PENDING_CONFIRM`时，sampleList返回所有已采集样本，供操作员预览挑选；
- 状态为`COMPLETED`时，finalResult返回经过字段映射、单位换算后的统一业务数据；
- 失败/超时状态，errorCode、errorMsg填充标准化错误信息，不返回底层串口原始报文。

### 4.4 接口3：任务取消 POST /api/device/task/cancel
入参
```json
{
  "taskId":"TASK-20261010-0001",
  "operatorId":"OP001",
  "cancelReason":"终止本次测量"
}
```
效果：任务状态置为CANCELLED，立即释放串口/USB端口资源，保存当前已采集样本。

### 4.5 接口4：提交选定样本 POST /api/device/task/submit（本地PC界面调用）
用于操作员在多组采样结果中选择一组作为最终测量结果。
入参
```json
{
  "taskId":"TASK-20261010-0001",
  "selectedSampleIndex": 1,
  "operatorId":"OP001"
}
```
执行逻辑：
1. 根据taskId取出对应样本原始硬件数据；
2. 通过paramMapping执行字段映射、单位换算，生成标准化业务finalResult；
3. 任务状态变更为COMPLETED；
4. 释放硬件端口资源。

> 对于数字化千分尺这类无需人工确认的设备：创建任务后，PC适配层自动完成单次测量，自动写入样本并自动提交，直接流转到COMPLETED，无需人工调用submit接口，一套模型兼容两类场景。

## 五、适配层内部完整执行流程
1. 上游调用`/task/create`，传入requestId、logicDeviceId、businessParams、taskTimeout；
2. PC适配服务读取**设备实例Mapping**，将logicDeviceId解析为physicalPort、deviceType、protocolProfile；
3. 读取**参数Mapping配置**，将上游businessParams转换为硬件指令参数；
4. 尝试打开物理端口、设备握手；
    - 握手失败 → 任务状态置FAILED，errorCode=DEVICE_NOT_READY，端口不占用；
    - 握手成功 → 状态更新DEVICE_READY，锁定该物理端口，同一端口同时仅允许一个任务；
5. 等待操作员触发测量；每次测量采集硬件原始数据，经过输出映射转换生成业务样本，追加到sampleList，状态更新MEASURING；可多次采集，持续追加样本；
6. 操作员完成测量，选择样本调用submit接口；千分尺设备自动执行该步骤；
7. 适配层生成finalResult（标准化业务数据），任务状态COMPLETED；
8. 任务完成/失败/超时/取消，自动释放端口锁，释放串口/USB资源；任务样本与日志保留一段时间后归档清理。

## 六、异常、超时与状态机处理机制
### 6.1 超时控制双层机制
1. 设备握手超时：任务进入CREATED后，尝试建立设备通信，在握手时限内无法连通，标记FAILED，错误码DEVICE_NOT_READY；
2. 全局任务超时：从任务创建开始计时，超过taskTimeout，无论当前任何状态，自动置TIMEOUT，强制释放硬件端口，保留已采集样本。

### 6.2 典型异常场景处理
1. 设备未就绪：上电失败、USB未插入、端口不存在 → FAILED，DEVICE_NOT_READY；上游可选择新建任务重试；
2. 测量中途设备断线（USB拔出、串口断开）→ FAILED，DEVICE_DISCONNECTED；自动释放端口，保留已采集的sampleList；
3. 串口通信间歇性报错：适配层内置有限次数通信重试；重试耗尽标记任务失败；
4. 卡在PENDING_CONFIRM，操作员长时间不提交 → 触发全局超时，状态TIMEOUT；
5. 端口被其他任务占用：创建任务直接返回FAILED，DEVICE_PORT_BUSY。

### 6.3 统一错误码清单
|错误码|说明|
| ---- | ---- |
|DEVICE_NOT_READY|设备未就绪，无法建立通信|
|DEVICE_DISCONNECTED|任务执行过程中断线|
|DEVICE_PORT_BUSY|物理端口已被其他任务占用|
|COMM_ERROR|设备通信报文解析失败|
|PARAM_MAPPING_ERROR|业务参数映射转换失败|
|TASK_TIMEOUT|任务全局超时|
|TASK_CANCELLED|任务被主动取消|
|INTERNAL_ERROR|适配服务内部异常|

> 所有错误信息向上游输出统一描述，不暴露底层串口原始报文、硬件内部报错文本。

## 七、内窥镜特殊适配
内窥镜同时返回测量尺寸数据+图像，Mapping配置扩展多媒体字段映射：
1. 硬件原始图像：可返回本地文件路径或Base64二进制；
2. 测量尺寸数据执行标准字段映射、单位换算；
3. sampleList中每个样本同时包含：测量业务数据+图像附件；操作员预览图片+测量尺寸后，选定样本提交。

## 八、并发与资源管控
1. 端口互斥锁：一个物理端口同一时刻仅允许一个任务，防止多任务抢占串口；
2. 任务隔离：不同taskId的数据隔离，样本数据存储在任务上下文；
3. 任务生命周期：任务完成/失败/超时后，保留样本与日志，设置过期清理时间，避免磁盘持续堆积；
4. 配置热加载：Mapping配置修改后，无需重启PC适配服务即可生效。

## 九、方案扩展规划
1. 新增设备：仅新增设备实例Mapping、参数Mapping配置，无需修改API接口、上游业务代码；
2. 设备列表查询接口：GET /api/device/list，查询PC本地所有logicDeviceId、设备在线状态；
3. Webhook回调：任务状态变更时，主动推送事件到上游业务系统，替代轮询；
4. 批量任务：支持一次创建多个独立测量任务，多个不同物理设备并行测量。

## 十、方案优势
1. 两层Mapping解耦：更换硬件品牌型号，上游业务完全无感；
2. 统一异步任务模型：同时支持千分尺自动单次测量、三坐标/内窥镜人工多次采样择一确认；
3. 完整状态机：覆盖设备未就绪、断线、超时、取消等全部异常场景；
4. 硬件资源安全：端口锁、自动释放，规避串口卡死；
5. 可扩展：新增设备只增加映射配置，接口结构稳定。
