# 部署与联调手册

> 本地开发启动顺序、EADAF/Electron 联调、Mock 种子数据说明。

## 1. 前置条件

| 组件 | 版本 | 说明 |
|------|------|------|
| Node.js | >= 20 | 推荐 24 |
| pnpm | >= 10 | 包管理 |
| EADAF API | 开发环境 | `http://localhost:29526` |
| EADAF 管理台 | 开发环境 | `http://localhost:29527` |

## 2. EADAF 侧准备（一次性）

1. **两个应用**：IPS 给排产，FMMS 给工位（code=FMMS, id=`10000000-0001-4000-8000-000000000006`）。数据模型只有 IPS 这一套。
2. **数据范围**：FMMS 应用要能调用 `IPS` 前缀的已发布服务。实体和字段以 `docs/EADAF数据结构设计-FMMS.md` 第 1 节为准，不要再按旧的 `fmms` 草案建模。
3. **采集管道**：`IPS/digital_measure`，写入 `IPS/inspection/InspectionRecord`。工位回调地址仍是 BFF `POST /api/collect/measurement`。
4. **SSO**：回调地址登记为跟随主机的 `:5181/auth/callback`（即 `http://localhost:5181/auth/callback`）。浏览器先打开 BFF `http://localhost:5180/auth/login`，授权完成后回到 5181，由前端转发到 BFF。令牌只留在 BFF。
5. **app_secret**：在密钥管理生成 app_secret，填入 `web/backend/.env.development` 的 `FMMS_APP_SECRET`。
6. **Token**：`POST /api/v1/applications/token` 用 application_id + app_secret 换取。

## 3. 本地开发启动

### 3.1 环境变量
```bash
cp web/backend/.env.example web/backend/.env.development
# 填写 FMMS_APP_SECRET
```

各子包会读取根 `.env` 或各自 `.env`（见各包 `.env.example`）。

### 3.2 启动顺序
```bash
# 1. 安装依赖
pnpm install

# 2. (确保 EADAF 已运行)

# 3. 启动全部（并行）
pnpm dev
```

或分别启动（推荐联调时分窗观察日志）：
```bash
# 终端1：BFF (web/backend)
cd web/backend && pnpm dev          # http://localhost:5180

# 终端2：前端 (web/frontend)
cd web/frontend && pnpm dev         # http://localhost:5181

# 终端3：工位客户端 (Electron)
cd app-workstation-client && pnpm dev # 弹出 Electron 窗口
```

### 3.3 端口分配

| 服务 | 端口 |
|------|------|
| EADAF API | 29526 |
| EADAF 管理台 | 29527 |
| web/backend (BFF) | 5180 |
| web/frontend | 5181 |
| Electron | — |

## 4. Electron 联调

### 4.1 首次启动配置
1. Electron 启动 → OP_BASE 未配置 → 自动打开配置页
2. 填写 web/frontend 地址（`http://localhost:5181`）、EADAF 地址、SSO 应用 ID
3. 点「测试连接」→ 保存
4. 主窗/副窗加载 OPWeb

### 4.2 单显示器调试
```bash
cd app-workstation-client && pnpm dev -- --small-secondary
# 副窗以小窗浮动，便于单屏开发
```

### 4.3 DevTools
- 主窗/副窗：`Ctrl+Shift+I`（webview DevTools）
- 配置页：同上

## 5. 种子数据

种子打到 IPS 的 Create，不写 `fmms` 工卡。工步仍写 `fmms/production/WorkStep`。

```bash
cd web/backend && pnpm seed
# 向 IPS 写入：
#   - 5 个工位（OP01–OP04，含 OP02-1 / OP02-2），stationType 为五种工位类型
#   - 每个工位类型 4 张工卡（待接受 / 修理中 / 修理完成 / 取消）
#   - 工卡零件、检验项、检验记录样例、线边库、测量设备
```

## 6. 采集联调（无硬件时）

Electron 采集服务内置 **mock driver**：
```bash
# 配置页或环境变量启用 mock
USE_MOCK_DRIVER=true pnpm dev
# 测量回调 POST /api/collect/measurement → IPS/digital_measure → 副屏检测表填充
```

有真实硬件时：
1. 在 IPS `MeasurementEquipment.connectionParams` 配置串口、地址等
2. Electron 采集服务自动发现并连接
3. 副屏故检工作台观察自动采集

---

## 7. SSO 联调

1. 确认 FMMS 应用 SSO 已启用，回调是 `:5181/auth/callback`
2. `web/backend` 的 `SSO_CALLBACK_URL` 为 `http://localhost:5181/auth/callback`
3. 浏览器打开 `http://localhost:5180/auth/login`，不要在 5181 上直接拼授权地址
4. 验证：`GET /auth/me` 返回用户信息；路由受 AuthGate 保护

**常见问题：**
- 回调地址不匹配 → 检查 EADAF 登记的重定向 URI 与 BFF `SSO_CALLBACK_URL`。登记的是前端端口 5181，由 Vite 转给 5180
- CORS → 检查 BFF `BFF_CORS_ORIGIN`

## 8. 验收检查清单（P1 最小闭环）

打通「登录→选故检工位→看到 Mock 工卡→副屏自动采集一条数据写 EADAF」：

- [ ] IPS 工位实体已发布，FMMS 应用可调用 `IPS` 前缀
- [ ] 采集管道 `IPS/digital_measure` 已发布
- [ ] BFF 启动，应用 token 获取成功
- [ ] 前端 OPWeb 启动
- [ ] Electron 配置 OP_BASE 后双屏加载 OPWeb
- [ ] SSO 登录成功，AuthGate 放行
- [ ] 工位选择故检1，持久化
- [ ] 工卡列表显示 Mock 工卡（故检类型）
- [ ] 接受工卡，状态更新
- [ ] 副屏检测表显示检测项（含标准值/公差）
- [ ] 采集（mock 或真实）一条数据 → 自动填充 + 判异
- [ ] EADAF InspectionRecord 有新记录（验证写入）
